Byte-order marks (hex), checked longest first so UTF-32LE is not read as UTF-16LE: UTF-32LE `FF FE 00 00`, UTF-32BE `00 00 FE FF`, UTF-8 `EF BB BF`, UTF-16LE `FF FE`, UTF-16BE `FE FF`. Only `FF FE` (and so UTF-32LE) collides with an existing rule today; checking all five makes the rule explicit.

MPEG audio frame header (ISO/IEC 11172-3 and 13818-3), four bytes: 11 sync bits; version bits (byte 1 bits 4-3): 00 MPEG-2.5, 01 reserved, 10 MPEG-2, 11 MPEG-1; layer bits (byte 1 bits 2-1): 01 Layer III, 10 Layer II, 11 Layer I, 00 reserved; byte 2: bitrate index (bits 7-4; 0 is free format, 15 is reserved), sample-rate index (bits 3-2; 3 is reserved), padding (bit 1); byte 3 bits 1-0: emphasis (2 is reserved).
Bitrates in kbit/s for index 1 to 14:
- MPEG-1 Layer I: 32 64 96 128 160 192 224 256 288 320 352 384 416 448
- MPEG-1 Layer II: 32 48 56 64 80 96 112 128 160 192 224 256 320 384
- MPEG-1 Layer III: 32 40 48 56 64 80 96 112 128 160 192 224 256 320
- MPEG-2 and MPEG-2.5 Layer I: 32 48 56 64 80 96 112 128 144 160 176 192 224 256
- MPEG-2 and MPEG-2.5 Layers II and III: 8 16 24 32 40 48 56 64 80 96 112 128 144 160
Sample rates in Hz for index 0 to 2: MPEG-1 44100 48000 32000; MPEG-2 22050 24000 16000; MPEG-2.5 11025 12000 8000.
Frame length in bytes (integer division, bitrate in bit/s): Layer I: (12 x bitrate / sample rate + padding) x 4; Layer II: 144 x bitrate / sample rate + padding; Layer III: 144 x bitrate / sample rate + padding for MPEG-1, 72 x bitrate / sample rate + padding for MPEG-2 and MPEG-2.5. The largest result is 2,881 bytes (MPEG-2.5 Layer II, 160 kbit/s, 8 kHz, padded).
Worked values for the tests: header `FF FB 90 64` is MPEG-1 Layer III, 128 kbit/s, 44.1 kHz, no padding, frame length 417; `FF FB 92 64` is the same with padding, length 418; `FF F3 80 C4` is MPEG-2 Layer III, 64 kbit/s, 22.05 kHz, no padding, length 208. The UTF-16LE text `FF FE` followed by "A" (`41 00`) reads as MPEG-1 Layer I, 128 kbit/s, 44.1 kHz, length 136, and no second header sits at offset 136 in text, so the tightened rule rejects it even without the mark check.

## Flagged assumptions

- **A mark means "let the name decide".** A UTF-16 text file misnamed `report.pdf` is recorded as `application/pdf` with no mismatch, the same as an ASCII text file misnamed `.pdf` today; the Phase 2 PDF converter then marks it unprocessed. Returning `text/plain` from sniff instead would turn every `.csv`, `.md` and `.json` with a mark into a false mismatch.
- **Already-recorded types are not re-detected.** A source recorded as `audio/mpeg` by an earlier scan keeps that type until its content changes (MIME is refreshed only for new content; review B-WR-09 is a separate warning). Only development and UAT scratch folders can hold such records; no release has shipped.
- **Layer I and Layer II stay recognised**, with full frame-length tables, so the rule stays general rather than becoming MP3-only.
