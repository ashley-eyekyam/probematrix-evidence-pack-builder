## Flagged assumptions

- **Skip, not fingerprint.** Following the verifier's and review CR-01's fix, a bad-named entry is listed as skipped, not registered: a lossy display key could collide and could not be mapped back to the file. The user renames it and scans again.
- **"No files found" message.** In a case with no sources and only bad-named entries, the scan message still reads "No files found in inputs/..." (as it does today for a folder holding only links); the BAD_NAME_IGNORED warning beside it explains the skip. Left unchanged to keep this fix small.
- **Open issues refresh.** As with links today, INDEX.md is rewritten only when a scan changes something, so a bad-named file added to an otherwise unchanged case shows in the warning at once and in INDEX.md on the next run that changes the case.
- **Pre-release schema change.** Adding `bad-name` to the enum is additive and needs no upgrade step; v0.1.0 is unreleased, so no older plugin reads these run records.
